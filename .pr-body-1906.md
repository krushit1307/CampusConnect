## Description

Adds a custom GraphQL `EmailAddress` scalar with validation and normalization, making email fields type-safe at the schema level.

### Changes

- **`graphql/resolvers/index.ts`**
  - Added `scalar EmailAddress` to the type definitions
  - Added `EmailAddress` resolver with `serialize`, `parseValue`, and `parseLiteral`
  - Validation: rejects non-string values and strings that don't match basic email format (`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`)
  - Normalization: converts to lowercase and trims whitespace on both serialization and parsing
  - Uses `GraphQLError` from the `graphql` package for consistent error reporting

The scalar can now be used in any schema field (e.g., `email: EmailAddress` instead of `email: String`), and validation happens automatically at the GraphQL boundary before resolvers execute.
